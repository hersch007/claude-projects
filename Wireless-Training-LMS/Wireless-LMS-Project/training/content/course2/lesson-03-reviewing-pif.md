## Overview

The Project Information Form is the foundation of every wireless facility application in AMP. Nothing moves forward without it. No components are activated, no fees are assessed, no Shot Clock begins, and no review can begin in earnest until the PIF has been submitted and reviewed.

As a Jurisdiction reviewer, the PIF is your first and most important opportunity to evaluate an application. What you find -- and what you decide -- at the PIF stage sets the course of the entire project. A PIF approved with an incorrect project type will generate the wrong components, the wrong Shot Clock, and the wrong fee schedule. A PIF approved with incorrect site information may route work to the wrong jurisdiction. A PIF that should have been sent back for revision but was not will carry its errors into every subsequent stage.

> **Key Point:** PIF review is not a formality. It is the single best opportunity to catch errors before they compound. An error identified at the PIF stage takes minutes to correct. The same error discovered after components have been completed may require restarting the entire application.

## What the PIF Contains

The PIF is divided into sections that capture the fundamental identity of the project. Every field has a purpose. Understanding each section helps you review efficiently and accurately.

### Section 1: Project Type

**This is the most critical field in the entire PIF.**

The project type determines:
- Which components are required (NWF, TWF, NCM, ATF)
- What fees apply
- Which regulatory pathway the project follows
- How long the Shot Clock is
- What federal provisions apply (standard review vs. Eligible Facility)

AMP project types include:

**Traditional Tower Projects:**
- New Tower
- Modification
- Colocation
- Eligible Facility / Colocation (EFC)
- Eligible Facility / Modification (EFM)
- Application Update

**Small Wireless Facility Projects:**
- New Small Wireless Facility / System
- Small Wireless Facility / System DAS
- Small Wireless Facility / System Modification
- Small Wireless Facility / System Colocation
- Small Wireless Facility / System Application Update

The difference between project types is not cosmetic. A carrier who selects "Colocation" when they are actually building a new tower from the ground up has misclassified the project -- and the wrong components will be activated, the wrong Shot Clock will apply, and your ordinance requirements for a new tower may not be triggered.

### Section 2: Jurisdiction and Site

This section identifies where the project is located and which jurisdiction is responsible for reviewing it. Verify:

- The jurisdiction selected matches your jurisdiction
- The site address or coordinates are consistent with your jurisdiction's boundaries
- The site information is complete (address, parcel, or coordinates as required by your ordinance)

A site submitted to the wrong jurisdiction is not an uncommon error, particularly for projects near municipal boundaries. If the site is in your jurisdiction but the Agent selected a neighboring municipality, send it back -- routing errors create gaps in the review record and may affect the Shot Clock.

### Section 3: Carrier and Agent Identification

This section identifies who is submitting the application and on behalf of which wireless carrier. Verify:

- The carrier name is present and corresponds to a known wireless carrier
- The Agent is registered in AMP for your jurisdiction
- Contact information is complete

An application submitted by an unregistered Agent or with inconsistent carrier identification is a completeness deficiency. It must be corrected before the application can proceed.

### Section 4: Project Description

The project description is the Agent's plain-language explanation of what is being proposed. It should be consistent with the selected project type. Common inconsistencies to watch for:

- Project type says "Colocation" but description mentions construction of a new ground-level monopole
- Project type says "Modification" but description mentions adding equipment at a height that exceeds the current structure
- Project type says "Small Wireless Facility" but description involves a traditional tower

When the description contradicts the project type, do not approve the PIF. Issue a revision request specifically identifying the inconsistency.

### Section 5: Eligible Facility Status

If the Agent has selected an Eligible Facility project type (EFC or EFM), a panel will appear in the PIF requiring the Agent to confirm that the project meets the federal Eligible Facilities Request criteria. The Agent must check a confirmation box acknowledging the applicable federal rules.

**Why this matters:** Eligible Facility applications have a presumption of approval under federal law (Section 6409(a) of the Middle Class Tax Relief and Job Creation Act). If the project meets the EFC/EFM criteria, your jurisdiction's ability to condition or deny the application is extremely limited. If the project does NOT actually meet the criteria, approving it as an EFC/EFM creates significant legal risk.

If the EFC/EFM criteria are not clearly satisfied, consult with your WTS Analyst and legal counsel before approving.

## Evaluating the PIF: The Reviewer's Checklist

Before approving a PIF, work through this checklist:

**Project Type**
- [ ] The project type accurately describes what is being proposed
- [ ] The description is consistent with the selected project type
- [ ] The Shot Clock length this type triggers is appropriate for the project

**Site and Jurisdiction**
- [ ] The site is within your jurisdiction's boundaries
- [ ] The site address or coordinates are complete and accurate
- [ ] The site matches any previously known project or site data in AMP

**Carrier and Agent**
- [ ] The carrier is identified
- [ ] The Agent is registered in AMP for your jurisdiction
- [ ] Contact information is present and complete

**Eligible Facility (if applicable)**
- [ ] If EFC/EFM is selected, the Agent has confirmed the criteria apply
- [ ] You have confirmed the project plausibly meets the federal criteria

**General Completeness**
- [ ] All required fields are populated
- [ ] No obviously inconsistent or contradictory information is present
- [ ] The application appears to be a genuine, good-faith submission

## Approving the PIF: What It Means

When you approve the PIF, you are making a specific legal determination:

**You are confirming that:**
- The project type is correct and the application is appropriately classified
- The site and jurisdiction information are accurate
- The Agent is properly registered and the carrier is identified
- The application is complete at the PIF stage and may proceed

**You are NOT confirming that:**
- The technical documentation is complete or adequate (that comes with component review)
- The project complies with all your ordinance requirements (full review happens later)
- The project will ultimately be approved
- Engineering is sound

Think of PIF approval as clearing the threshold -- the application has the correct identity and can be admitted for full technical review. The real work begins after PIF approval.

## Issuing a PIF Revision Request

When the PIF has a deficiency that prevents approval, you must issue a revision request inside AMP. The revision request must:

1. **Identify the specific deficiency** -- not a general statement that the form is incomplete
2. **Reference the relevant field or requirement** -- which field is wrong, missing, or inconsistent
3. **Be actionable** -- the Agent should be able to read your revision request and know exactly what to correct

### Examples of Valid PIF Revision Requests

**Valid:** "The project type selected is Colocation. However, the project description states that a new monopole structure will be installed at this site. If a new structure is being added, the correct project type is New Tower. Please review and correct the project type to match the proposed work, or revise the project description to clarify that this is a colocation on an existing structure."

**Valid:** "The site address provided in the PIF (123 Oak Street) does not appear to be within [Jurisdiction Name]'s boundaries. Please confirm the correct site address and verify the appropriate jurisdiction."

**Valid:** "The Agent of Record listed in this application does not appear to be registered in AMP for [Jurisdiction Name]. Please confirm the Agent's registration status before resubmitting."

### Examples of Invalid PIF Revision Requests

**Invalid:** "Please correct and resubmit." (Not specific enough -- what needs to be corrected?)

**Invalid:** "The application is incomplete." (Which fields? What is missing?)

**Invalid:** "We need more information about this project." (What information? What specific requirement is not met?)

Vague revision requests are not only unhelpful -- they may not constitute a valid completeness determination under federal law, which affects the Shot Clock. A properly documented, specific revision request creates a defensible record. A vague one does not.

## After PIF Approval: What Happens Next

When you approve the PIF, AMP automatically:

1. **Activates the required components** for the selected project type
2. **Calculates the application fees** based on project type and jurisdiction configuration
3. **Generates an invoice** for the Agent
4. **Continues the Shot Clock** countdown

The Agent is immediately able to begin completing the component forms -- this is a May 2026 platform update. Previously, Agents had to wait for payment confirmation before working on components. Now they can open and complete components immediately after PIF approval. They cannot, however, **submit** the components until payment is confirmed.

> **Key Point:** PIF approval triggers component activation and fee generation simultaneously. If the project type was incorrect when you approved it, the wrong components were activated and the wrong fees were calculated. This is why PIF review -- especially project type verification -- is so important before approving. Correcting a project type after components are activated requires administrative steps that delay the entire application.

---

## Key Takeaways

- The PIF is the foundational document of every application. Errors at this stage cascade into every subsequent stage.
- The project type selection is the single most consequential field in the PIF. It drives components, fees, Shot Clock length, and regulatory pathway.
- Review the PIF against a checklist: project type accuracy, site and jurisdiction match, carrier and Agent identification, Eligible Facility criteria if applicable.
- PIF approval is a threshold determination -- you are confirming the application has the right identity and can proceed to technical review. It is not a commitment to ultimate approval.
- Revision requests must identify specific deficiencies and be actionable. Vague requests are not legally defensible and may not constitute a valid completeness determination.
- After PIF approval, components activate, fees are calculated, and the Agent can begin component work immediately. The Shot Clock continues.
